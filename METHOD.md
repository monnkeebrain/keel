# KEEL — METHOD

Operating manual for any agent (or human) working in this repo.
Adapters are generated from this file. Do not edit adapters directly.

Status: v0.2 — protocols defined, toolchain live. Keep every section
minimal enough to be unambiguous; ambiguity here becomes thrash in
every future session.

## 0. Reading order for a fresh session

1. Read `STATE.md` (bounded snapshot + resume cue)
2. Read the law slices relevant to your task (see pack or ask operator)
3. Read the target story in `data/stories.json`
4. Work. Then: update STATE.md, append residue to `decisions.md`, commit.

Bootstrap ritual: if an origin is configured, `git pull --ff-only` before
anything else; if not (local-only mode), go straight to STATE.md.
Local-only is a first-class mode, not a degraded one.

Remotes: when work must sync across machines/instances, use a private
GitHub or GitLab repository. Keel requires nothing from hosting beyond
push/pull — pick whichever your team already has.

## 1. Invariants (Tier A — change rarely, see AMENDMENTS.md)

1. Everything that matters lives in this repo, never only in a harness.
2. STATE.md stays bounded: O(current), never O(history).
3. No done without evidence mapped to AC/DoD.
4. One canonical store (`data/`, `laws/`, `decisions.md`);
   pages/views are projections.
5. Raw history goes to `archive/`; durable lessons get distilled into
   `decisions.md`.
6. IDs (story ids, law keys) are immutable once referenced anywhere.
7. Adapters are build artifacts; METHOD.md is their only source.
8. Complexity must pay rent.

## 2. Artifacts

| Path | Role | Mutability |
|---|---|---|
| `laws/*.md` | standing constraints: stack, design, domain rules | versioned, append new versions |
| `data/stories.json` | contracts: narrative, AC[], DoD[], status | append/edit pre-ready; locked at launch |
| `decisions.md` | residue: rationale + consequences, newest first | append-only; corrections via supersede |
| `STATE.md` | live snapshot: phase, open intents, next step | regenerated freely |
| `archive/log-*.md` | raw history | write-once |

Story schema v0 = the validated 12-story corpus in `data/stories.json`
(id, epic, priority, title, as_a, i_want, so_that, ac[], dod[], status).
Do not extend fields without an AMENDMENTS entry.

Projections (never hand-edit):
- `overview.html` — human decision surface. Generated by `bin/render`.
  Required panels: currency header (phase/time/HEAD) · needs-me
  (review/blocked/open questions) · progress counts · in-flight with age ·
  stale/problems (gate failures, evidence gaps) · recent decisions ·
  resume cue verbatim. Design laws: numbers over adjectives, zero
  decoration, mono IDs, glanceable first, works from file://, no JS
  framework, no build step. Pre-P1 absence must be labeled, never
  faked by hand.
- Root `AGENTS.md` / `.hermes.md` and `adapters/owui-system-prompt.md` —
  machine entry points, generated by `bin/adapt` from this file.
  Root files are committed so fresh clones pass native discovery
  (F-004/F-005 lesson: discovery paths must meet the artifact). See §5.

## 3. Protocols (Tier B — amendable)

### P-BOOT Session bootstrap
Every session starts here — including "quick questions". No exceptions.

1. Work only inside the repo root. Not in a repo → stop, ask operator.
2. Sync truth:
   - Origin configured → `git pull --ff-only` (fresh environment:
     clone first). Pull fails → STOP and report. Never merge, never
     force.
   - No origin → say `origin: none — local mode`, continue; local
     HEAD is canonical. [A-002, in trial]
3. Read `STATE.md` completely.
4. Read METHOD §1 (invariants). If your adapter's summary and the repo
   disagree, the repo wins.
5. Route the task:
   - Story ID given → load that story + its referenced law slices only.
   - No task given → reply with phase, open intents, resume cue,
     ready count. Then wait. Do not invent work.
6. Emit the BOOT line so the operator can verify you read state:
   `BOOT ok · <phase> · <n ready> · <resume cue>`
7. Only now may work begin.

Forbidden until the BOOT line is emitted: editing/creating files,
running bin mutations, committing, branching, installing anything,
"improving" documentation.

Staleness check: STATE.md carries generated-at. If it predates the last
commit materially (>24h), flag it to the operator before working.

Reporting law (from F-001): any "done" claim leaving a session must cite
its evidence — commit hash or artifact path. Reports without evidence
are void and must be treated as not happened.

### P-STORY Contract flow
capture intent → draft story entry → `bin/gate US-xx` passes →
operator signs (commit message: `sign US-xx`). No self-promotion to
ready without the sign commit.

### P-RUN Execution flow
`bin/pack US-xx` → execute within scope → verify each AC/DoD →
report evidence list → operator accepts/rejects → status update +
decision entry if material → commit `accept US-xx`.

### P-END Session end
1. Regenerate `STATE.md`: `bin/state` (update resume cue if the frontier
   moved: `bin/state --cue "…"`).
2. Append residue: material outcomes → `decisions.md`; raw narrative →
   `archive/`. Failures → `FAILURES.md`, immediately, fact form.
3. Commit: `<verb> <ref> · <summary>` (e.g. `accept US-04 · …`).
4. Push. Push fails → say so loudly: unpushed state is not truth.
5. Report ends with evidence: commit hash + changed artifacts.

### P-DISTILL Compaction ritual
At phase end or when archive grows: run distill, move raw log to
`archive/`, keep decisions.md tight. STATE.md regenerated after.

## 4. Toolchain

`bin/keel` dispatcher plus thin wrappers: `bin/gate` · `bin/pack` ·
`bin/state` · `bin/distill` · `bin/render` · `bin/adapt` · `bin/boot` ·
`bin/verify` · `bin/init`.
Stdlib Python only — no pip installs — so it runs identically in OT slim
containers, VPSes, and locally. Invocation: `bin/gate US-04`,
`bin/state --cue "…"`, `bin/render`, `bin/adapt`, `bin/verify`, `bin/boot`.
Run `bin/init` once inside a fresh clone to start a NEW project workspace:
it empties stories/decisions/ledgers/archive and creates `src/` for project
code, leaving method files untouched. Run `bin/verify` after any manual repo
surgery or before trusting an unfamiliar local copy — it exits non-zero on
schema/adapters problems.
